# Releasing yuanme

How the Engine is built, signed and shipped. Decided in [How is yuanme distributed, versioned and updated?](https://github.com/yuann3/yuanme/issues/37) and [ADR 0015](adr/0015-what-is-public-api.md); built in [#78](https://github.com/yuann3/yuanme/issues/78).

## What a release is

`.github/workflows/release.yml`, generated by dist 0.32.0 from `dist-workspace.toml`, runs when it is dispatched with a tag:

1. **Build.** Six archives: `x86_64` and `aarch64` for `unknown-linux-musl`, `apple-darwin` and `pc-windows-msvc`. Each holds the binary, `README.md`, `LICENSE-MIT`, `LICENSE-APACHE` and `THIRD_PARTY_NOTICES.md`, and has a `.sha256`. dist also writes the shell and PowerShell installers, the Homebrew formula and `sha256.sum`.
2. **Gate.** Three jobs must pass before anything is published:
   - `ci.yml`, all of it;
   - `release-smoke.yml`: each archive, on its own platform, has its checksum and exactly those files, and its binary reports the release's version and builds a Site. The Linux binaries are static. The run's summary lists each platform's hash of that Site. Its `starters-lab` job makes each Starter with the `x86_64` Linux binary and checks, in Chromium on Lighthouse's mobile throttling, that the home Pages and the blog's Post have an LCP of at most 2.0 s and a CLS of at most 0.01 (#36);
   - `release-sign.yml`: writes `sha256.txt`, the hash of each archive, and signs it as `sha256.txt.minisig`, with the trusted comment `yuanme vX.Y.Z`.
3. **Publish.** The GitHub Release, with GitHub attestations for every file, which also makes the tag. Then `release-crates.yml` publishes every crate to crates.io, and dist commits the formula to `yuann3/homebrew-tap`.

The default tag, `dry-run`, does steps 1 and 2 and publishes nothing. It signs with a key it makes and throws away, and makes no attestations.

```sh
gh workflow run release.yml -f tag=dry-run
```

Its archives are the run's `artifacts-build-local-*` artifacts; the dry run's public key is its `minisign-public-key` artifact.

## Before the first release

These need the owner's accounts, once.

1. **Reserve the crate name** with a placeholder at 0.0.0, before any announcement (#37), so the first real release can be 0.1.0:
   ```sh
   mkdir -p /tmp/yuanme/src && cd /tmp/yuanme
   cat > Cargo.toml <<'EOF'
   [package]
   name = "yuanme"
   version = "0.0.0"
   edition = "2024"
   description = "A static site generator for Markdown, Org and math. A placeholder until the first release."
   license = "MIT OR Apache-2.0"
   repository = "https://github.com/yuann3/yuanme"
   EOF
   echo 'fn main() {}' > src/main.rs
   cargo publish --allow-dirty
   ```
2. **A crates.io token** with the `publish-new` and `publish-update` scopes, limited to crates matching `yuanme*`, from <https://crates.io/settings/tokens>. The first release publishes nine crates crates.io hasn't seen:
   ```sh
   gh secret set CARGO_REGISTRY_TOKEN --repo yuann3/yuanme
   ```
3. **The Homebrew tap**, and a fine-grained token with *Contents: read and write* on it alone:
   ```sh
   gh repo create yuann3/homebrew-tap --public --description "Homebrew formulae for yuanme"
   gh secret set HOMEBREW_TAP_TOKEN --repo yuann3/yuanme
   ```
4. **The minisign key.** The secret key goes in a secret, and the public key into the repository, where `release-sign.yml` checks the signature against it and `yuanme self update` (#79) embeds it:
   ```sh
   minisign -G -p crates/yuanme/src/minisign.pub -s ~/.minisign/yuanme.key
   gh secret set MINISIGN_SECRET_KEY --repo yuann3/yuanme < ~/.minisign/yuanme.key
   gh secret set MINISIGN_PASSWORD --repo yuann3/yuanme
   git add crates/yuanme/src/minisign.pub
   ```
   Keep a copy of the secret key offline. A key made with `-W` has no password; then leave `MINISIGN_PASSWORD` unset.

## Each release

```sh
cargo xtask release-version X.Y.Z   # yuanme at X.Y.Z, the library crates at the next 0.0.N
# add an X.Y.Z section to CHANGELOG.md: Breaking, Added, Fixed, Output changes (#37)
git commit -am "Release X.Y.Z" && git push origin HEAD:main
gh workflow run release.yml -f tag=vX.Y.Z
```

dist takes the release notes from CHANGELOG.md's section for the version. The file starts with the first release.

A version with a suffix, such as `v0.2.0-rc.1`, is a prerelease: it gets a GitHub Release, and no crates or formula.

## Checking a download

```sh
gh attestation verify --repo yuann3/yuanme yuanme-x86_64-unknown-linux-musl.tar.xz
minisign -V -p minisign.pub -m sha256.txt
sha256sum --ignore-missing -c sha256.txt
```
